# V2.1 local app slice

The selected scope is G0–G3 of [the implementation contract](DIWALI_SPEC.md). Exactly four logical roles participate in each Diwali case: manager, researcher, skeptic and builder. Local transport has distinct identities and inboxes. It dispatches immutable inputs to three separate worker handlers; the manager's pure reducer controls transitions. No SQLAlchemy session crosses an actor boundary. The researcher reports candidates rather than eligibility, the skeptic independently calls the existing matcher, and the manager rechecks its result. Only verified cases reach the deterministic builder and existing composer.

The coordinator serializes fixture products in input order. It commits outgoing intent before dispatch and couples accepted consumption, revision and new intent in one transaction. Domain finalization uses `diwali/legacy_bridge.py`; the staging implementation never calls legacy commit-owning helpers. A case's frozen purchase/source facts survive replacement of legacy evidence. Approval/export continue through existing packet routes with additional digest checks for Diwali packets. Unknown schema versions stop startup rather than rebuilding tables.

`DIWALI_ENABLED` defaults to false. Local mode requires synthetic demo purchases and at most five distinct inputs. BAND admission returns 503 until its provider gate is implemented; it cannot silently become local mode. Cached status GETs do not call vendors. Configuration presence is separate from observed health and proof.

The manager enforces a 90-second maximum run, five-second finalization reserve, ten-second maximum task, twelve application messages per case and at most one public follow-up. Lower configured bounds are enforced. No paid retry, provisioning, claim submission or automatic approval exists. Missing purchase model asks the user; unresolved public facts terminate after one follow-up. Failures close pending work and preserve accepted evidence. Restart cancels pending tasks and requires an explicit new run.

The local UI uses existing run/opportunity/packet screens, an explicit mode selector, separate LOCAL TEST / SOURCE RECORDED badges, accepted-message timeline and purchase/source comparison. Polling remains 800 ms. Recorded local test data is not BAND proof. No provider SDK, runtime framework, dependency upgrade, deployment or publication belongs to this gate.
